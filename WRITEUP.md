# wdiff: a semantic diff for model weights

`git diff` tells you which lines changed. For two checkpoints of the same model, the equivalent answer, "these 130,188 floats differ", is true and useless. wdiff tries to say what changed, in the form a commit message would: where the edit lives, what shape it has, and what the model now does differently.

It works at three levels, plus a summarizer:

1. **Structural.** Which tensors changed and by how much: count, Frobenius ratio, cosine.
2. **Directional.** The SVD of each ΔW. A rank-1 ΔW means every edited column moved along the same vector, so the edit is one direction. We report the rank and the top direction. We fit the scale α in c′ = c − α(c·v)v and compare directions across layers and against a refusal direction computed for the base model (difference of means, Arditi et al., 2024).
3. **Behavioral.** Both models run the same probe sets with the same sampling seed: 50 GSM8K problems, 20 harmful prompts and 20 harmless ones. We compare loop, answer, accuracy and refusal rates.
4. **Summarizer.** One LLM call turns the three JSON reports into a commit message with a fixed shape: title, Where, What, Effect, Unchanged, Confidence. Weights never enter the prompt: it gets statistics only, a guard rejects any list longer than 16 numbers, and a token check holds the input under 3,000 tokens. Every number in the reply must match a number in the reports, possibly rounded or written as a percent. Otherwise the message is rejected and saved as `COMMIT.rejected.md`.

## The two commit messages

**Pair 1:** `Qwen/Qwen3.5-0.8B` vs `RikiyaT/Qwen3.5-0.8B-weight-space-programming`, a published edit that fixes reasoning loops.
**Pair 2:** `meta-llama/Llama-3.2-1B-Instruct` vs `mylesgoose/Llama-3.2-1B-Instruct-abliterated`, a community "abliteration" with no description of how it was made.

Both messages were generated by `claude-opus-5-5` from the reports alone, with no hints about what to expect. Excerpts below, verbatim; the full messages are in `reports/*/COMMIT.md`.

## What it got right

**It found the Qwen edit exactly.** The published fix lives in `mlp.down_proj` of layers 15 and 19, confined to 64 columns. wdiff recovered that, along with 131,072 weights in the edited columns. 130,188 of those actually differ on disk; the other 884 round back to their stored bf16 value.

**It found something the description didn't say.** The edit is described as removing a direction. The fit says otherwise: each column is c − **6**(c·v)v. The component along v isn't zeroed. It's flipped and grown to five times its size. The fit residual is 0.002, about the size of bf16 rounding. One plausible cause is a projection onto an unnormalized direction with ‖r‖² = 6.

**It kept the two Qwen layers apart.** The spec expected the two layers to share one direction (cos > 0.9). The measurement is cos 0.849: related, but not the same.

**It passed the negative control.** The Qwen loop direction is not the refusal direction (|cos| 0.007 and 0.019).

**It didn't take the Llama label at face value.** "Abliterated" usually means one refusal direction projected out of every layer. We expected exactly that: rank 1, high cosine with refusal. What wdiff found instead:
- **Rank 15.** Every ΔW has exactly 15 singular values above the bf16 noise floor, then a cliff.
- **One subspace everywhere.** All 33 tensors share the same 15 dimensions (overlap ≥ 0.9995).
- **Barely the refusal direction.** The refusal direction, valid with held-out AUC 1.000, is barely inside that subspace: at most 5.9% of its energy, against 0.73% for a random direction.
- **A partial behavioral effect.** Refusals fall only from 0.90 to 0.70, and the edited model still refuses 14 of the 18 harmful prompts the base refuses.

The summarizer wrote all of this down and said confidence is low because "it is unclear what the edit actually removes". That's the honest answer, and it's the main reason the tool is worth having.

## What it got wrong, or did badly

**The loop metric was flawed.** Phase 3 had a gate: the math loop rate should fall by 20 points. It fell by 4, from 0.92 to 0.88, at 1,024, 4,096 and 8,192 tokens. Meanwhile the edited model finished more problems: math accuracy rose from 0.12 to 0.32, and hitting the token cap fell from 0.88 to 0.64. The "repeat" half of the metric flags thinking-mode math that re-checks its own lines. For example, `Total = 4 + 12 + 2 = 18` written three times counts as a loop. In the edited model's finished math answers, it flagged 12 of 18, and 10 of those were correct. The gate is kept as specified and marked as a known failure, not redefined after the fact.

**The refusal rates mislead.** On Qwen, the refusal rate "rose" from 0.25 to 0.75. Mostly that's because 60% of the base model's harmful-prompt runs never finished thinking, so there was no response to count as a refusal. Both Qwen messages flag the confound.

**The summarizer is not reliable on numbers by itself.** In four Qwen runs:
- One draft was rejected by a bug in the checker, which split `3.6e-04` into two numbers.
- One was rejected correctly: it wrote "486 of 488 tensors are unchanged", a number it computed, not copied.
- The accepted Qwen message still overstates once. It says looping dropped "on every probe set", but math moved only from 0.92 to 0.88, as its own Unchanged line says.

The number check catches invented numbers, but it can't catch a wrong claim built from correct ones. The messages also ignore the template's one-line-per-field shape and run to paragraphs.

**The context budget is tight.** The Llama context first came to 4,024 tokens and had to be grouped by tensor kind to fit. It now sits at 2,994, against a limit of 3,000. A model with more tensor kinds will need a smarter summary.

**Our expectations were wrong more often than the tool.** The spec had the Qwen fraction as 0.016%; the measurement is 0.015%. It expected rank 1 on Llama and a positive refusal control. The tool reported what it measured each time.

## What it cannot do

- **No behavior from weights alone.** The directional level can say "rank 15, shared across 33 tensors". It can't say what those 15 dimensions mean. Meaning comes only from probes and named directions you thought to compute. Here that was a single refusal direction.
- **One architecture per pair.** Both checkpoints must have the same tensor names and shapes.
- **Small probes.** With 20 to 50 prompts and one sample each, a 20-point move is about the smallest change worth believing.
- **No provenance.** wdiff can describe the Llama edit, but not how it was made. The fitted scale per direction falls from 1.1 to 0.18, which fits several non-orthogonal directions projected out in sequence. That is a guess.

## Reproduce

```bash
uv sync --extra summarize
uv run wdiff all Qwen/Qwen3.5-0.8B RikiyaT/Qwen3.5-0.8B-weight-space-programming --out reports/qwen3.5-0.8b-wsp --directions directions/qwen3.5-0.8b --batch-size 16 --max-new-tokens 8192 --force
uv run wdiff all meta-llama/Llama-3.2-1B-Instruct mylesgoose/Llama-3.2-1B-Instruct-abliterated --out reports/llama3.2-1b-abliterated --directions directions/llama3.2-1b --batch-size 16 --max-new-tokens 8192
uv run pytest
```

Behavioral runs take about one hour (Llama) to two (Qwen, which thinks at length) on an Apple M5 Max. The summarizer needs `ANTHROPIC_API_KEY`. Both report directories are checked in, with exact model revisions in each JSON file's `meta` block. In `samples/refusal_20.jsonl`, completions not scored as refusals are redacted (scores and a sha256 kept); a rerun regenerates them. Apache-2.0.
